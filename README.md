# Marginalia

A book recommendation engine for those looking to travel more knowledgeably, or read what the people they look up to read.

Two flows, a short curated list each (up to five), no doomscrolling:

- **Literary Travels** — enter a destination and your genre preferences. Get a short reading list (rated 3.8+ on Goodreads) that deepens your understanding of the place before you land. Includes a demo "connect Goodreads/Fable" toggle that simulates excluding books already on your shelf.
- **Read Like a Pro** — enter public figures you admire and get a short reading list (rated 3.4+ on Goodreads) they've publicly recommended, filtered by genre.

## Running it

```bash
npm install
npm run dev
```

Then open the printed local URL. `npm run build` produces a static production build in `dist/`, deployable to any static host (Vercel, Netlify, GitHub Pages, etc.) — there's no backend.

## How the data works

There's no live Goodreads API to call — Goodreads shut down public API access to new developers in 2020, and there's no public API for scraping celebrity interviews either. The catalog is three sources merged at runtime (`src/lib/catalog.ts`), unioned by title+author so a book that appears in more than one source keeps every source's fields (a location tag from one and a `recommendedBy` from another, say) instead of one clobbering the other:

- **`src/data/books.ts`** — a small, hand-curated set (~90 books) with editorial "why this place" copy and `recommendedBy` attributions. Every attribution is limited to something genuinely, publicly documented — annual reading lists (Obama, Gates), book clubs (Reese's, Emma Watson's), GatesNotes, and similarly attributable sources, described generally rather than invented as verbatim quotes.
- **`public/data/travel-catalog.json`** — an ~8,900-book catalog generated by `scripts/transform_kaggle.py` from a real Kaggle Goodreads export (title/author/rating/genres/setting, all real, not fabricated), filtered down to only books with a real-world setting tag (the only ones "Literary Travels" can ever surface — untagged books are dropped rather than shipped for no benefit).
- **`public/data/recommender-catalog.json`** — ~760 books generated by `scripts/transform_recommenders.py` from a public-figure-recommendations dataset (title/author/who recommended it), joined against the same Goodreads ratings data for a real, non-fabricated rating (the recommendations CSV itself carries no rating). Covers ~260 public figures. Each person's `role` (what they're known for) is filled in by hand for names confidently, factually identifiable (~80% coverage); the rest fall back to a neutral "Public figure" rather than a guessed specialty. `context` is deliberately generic ("Cited in public interviews, podcasts, or reading lists") rather than a fabricated specific citation, since the source data doesn't carry a per-book citation of exactly where someone recommended a title.

Both bulk JSON files are fetched at runtime rather than bundled into the JS chunk, so they don't bloat the app's load size.

To refresh or grow either bulk catalog:

```bash
python3 scripts/transform_kaggle.py path/to/goodreads-export.json
python3 scripts/transform_recommenders.py path/to/recommenders.csv path/to/goodreads-export.json
```

Shared parsing/mapping logic (genre taxonomy, ISBN validation, title/author normalization for cross-dataset joins) lives in `scripts/_shared.py`. See the scripts for exactly what they do — notably `extract_location_tags` (turning Goodreads' free-text "setting" field into location tags, with safeguards against short ambiguous place names like "York" false-matching a "New York" search — paired with `placeMatches` in `src/lib/recommend.ts`) and `norm_loose` (the fuzzy title/author key used to join the recommenders CSV against real ratings, since it carries none itself).

**Book covers** are fetched live from the [Open Library Covers API](https://openlibrary.org/dev/docs/api/covers) by ISBN, with a generated placeholder cover as a graceful fallback if an image is missing or Open Library has no cover for that ISBN.

To go further toward production, the natural next step is a real backend pulling live ratings from a licensed source (e.g. a Goodreads data partner) and a moderated pipeline for sourcing new celebrity-recommendation citations. `src/lib/recommend.ts` already operates on a plain `Book[]` pool passed in by the caller, so swapping the data source doesn't touch the UI.

## Stack

Vite + React + TypeScript + Tailwind CSS. No backend, no database — everything runs client-side against the curated dataset.
